## 1. Scope / Goals

**Goal:** every app deploys to the web servers as **its own Linux user, with its own key**, and that
user can touch only its own app. `glyphadmin` goes back to being the admin account only.

**Why (found 2026-11-01, see Mimir runbook MIM00.11):** every app logs in as `glyphadmin`. Separate
keys per app gave no separation on the server: any app's key can overwrite every app's files under
`/opt`, read their `appsettings` (database passwords), and restart their services. Ravenhold's key
also opens the **admin** accounts on both database servers.

**In scope**
- Web servers GlyphScribe (test) and GlyphWarden (production).
- Apps: **Mimir** (first, nothing live yet), Exchequer, Ashborne, Sovereign, Ravenhold.
- Ravenhold's setup scripts (`setup-db.ps1`, `setup-web.ps1`) move off its deploy key onto the
  user's admin key; its key comes off `hephaestusadmin` and `vulcanadmin` (user's decision 2026-11-01).
- Each app's deploy scripts, local config, manuals; cert reissue scripts that log in as the deploy user.

**Not in scope (parked, §5):** EagleEye (no SSH deploy to the web servers); the shared SSH host key
of GlyphScribe/GlyphWarden; SQL Server logins.

**Guiding principles**
- **Add before remove.** The new user and key work alongside `glyphadmin` until a real deploy with the
  new user succeeds. Old keys come off only at the end of each app, with the user's yes.
- **Test before production**, one app at a time. A production deploy runs only on the user's go-ahead.
- **Prove the separation**, don't assume it: each app ends with a check that its user is refused on
  another app's files and service.
- Passwords and passphrases are typed at runtime, never stored. Server files are edited with `nano` /
  `visudo`, never pasted heredocs.

## 4. Phases

### The pattern (applies to every app phase)
Per app `<app>`, on each web server:
- **User** `<app>deploy`: normal login user, shell `/bin/bash`, home `/home/<app>deploy`, no password
  (key only), member of **only** its own runtime group.
- **Key**: one per app per dev PC, `D:\repos\.config\<app>\<app>-deploy.key`, ed25519, **with a
  passphrase**, comment `<app>-deploy@Nidavellir-PC`, file locked to the user (`icacls`), loaded into
  ssh-agent. One line in `~<app>deploy/.ssh/authorized_keys`:
  `from="<DSEP00.02 address>",restrict ssh-ed25519 AAAA… <app>-deploy@Nidavellir-PC`
  (`restrict` turns off port, agent and X11 forwarding and the terminal; DSEP01.03 checks no deploy needs a terminal.)
- **Files**: `/opt/<app>` and its `logs`, `certs`, `appsettings*.json` owned by `<app>deploy:<group>`;
  `keys` stays with the service user.
- **Sudo**: `/etc/sudoers.d/<app>-deploy`, edited with `visudo -f`, holding today's rule (§2.3) with
  `glyphadmin` replaced by `<app>deploy`.
- **Proof of separation**: as `<app>deploy`, writing into another app's `/opt` folder, reading its
  `appsettings`, and `sudo -n systemctl stop <other app>` are all refused.
